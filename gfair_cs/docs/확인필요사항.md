# 확인필요사항

기준일: 2026-11-06 (한국 시간) · 정리본 v1.0

현재 화면 동작을 임의로 바꾸지 않고 별도로 결정·연동해야 할 항목이다.

## Q01 엑셀 오류 반영 단위의 불일치

우선순위: P1 · 근거: S09, S10

- 현재 확인: 현재 검증·화면은 오류 1건 이상이면 전체 미반영한다. 과거 정상 행 부분 반영 요청과 일부 업로드 Description은 다른 기준이다.
- 다음 결정/처리: 현재 전체 실패를 유지할지 정상 행 부분 반영으로 바꿀지 확인한 뒤 코드·Description·규칙을 한 번에 맞춘다.

## Q04 QR 상태 전이·정정

우선순위: P1 · 근거: S15

- 현재 확인: QR 선택 화면은 입국·호텔 이동·호텔 도착·전시장 출발·전시장 입장·통역원 만남·전시장 퇴장을 제공한다. 해외바이어 상세 이력에는 상담 시작·종료 등 다른 단계 정의가 있다.
- 다음 결정/처리: QR 상태와 방한 상세·출결·상담 이력의 대응표, 역순·건너뛰기·재입장·정정 및 통계 집계 기준을 확인한다.

## Q05 설문 1회 제출의 서버 판정

우선순위: P1 · 근거: S18, S19

- 현재 확인: Description은 설문 ID·연도·응답자 고유코드의 1회 제출을 정의한다. 국내바이어는 목업에서 제출 후 빈 설문으로 돌아가는 반복 시연 예외가 있다.
- 다음 결정/처리: 운영 서버의 중복 제출 방지·저장 완료 판정·실패 복원을 구현하고 목업 예외가 운영에 적용되지 않도록 확인한다.

## Q06 구매·수출 일지 상태 명칭

우선순위: P2 · 근거: S11, S12

- 현재 확인: 수출 일괄 처리는 작성 중/반려를 사용한다. 다른 코드에는 임시 저장도 존재한다.
- 다음 결정/처리: 유형별 상태코드·노출명·수정/삭제/재제출 가능 여부 표를 완성한다.

## Q07 메뉴 접근과 처리 권한

우선순위: P2 · 근거: S01, S13

- 현재 확인: 메뉴의 △는 단일한 수정/열람 권한으로 해석할 수 없다.
- 다음 결정/처리: 담당 범위·행사·목록·상세·버튼·서버 API 단위 권한표를 연결한다.

## Q08 상세 Description과 운영 산식 검토

우선순위: P2 · 근거: S02

- 현재 확인: 현재 문서가 여러 화면에 영향을 주는 공통 기준을 관리한다. 개별 항목·알럿·핀과 일부 예시 값·과거 설명은 저장 Description에 남아 있다.
- 다음 결정/처리: Description의 오타·노출 조건과 통계 산식·개인정보 이력 보존 기간을 업무별 검토한다. 문서 정리를 이유로 설명과 댓글을 일괄 삭제하지 않는다.

## Q09 데이터 저장 수준

우선순위: P2 · 근거: S05, S15, S19

- 현재 확인: 참가 상태·QR 기록·설문 작성값 등은 현재 메모리 또는 탭 저장 예제가 섞여 있다.
- 다음 결정/처리: 새로고침 복원·동시 작업·중복 실행·서버 장애·감사 로그 보존 기준을 정한다.

## Q10 승인된 표준상담일지 변경의 연결·배포 확인

우선순위: P1 · 근거: S11, S12

- 현재 확인: 표준상담일지 모듈과 문서는 저장소에 있으나 기준 공개 소스의 index.html·app.js에는 모듈 진입 연결이 없다. 구매 만원/KRW·수출 USD 예외는 사용자 확정사항이다.
- 다음 결정/처리: 기업 확인·상담수준 C1~C5·후속조치·250자 검증 등의 연결·Description·배포를 별도 완료한 뒤 현행 화면 기준으로 승격한다.

## 승인됐지만 공개 연결을 확인하지 못한 표준양식

- 구매는 만원 입력·원(KRW) 저장, 수출은 USD 유지한다는 사용자 예외를 보존한다.
- 기업 확인, 상담일자, C1~C5 상담수준, 보완사항, 상담액·조건부 계약추진액, 금액 미산정·공란/0 구분, 후속조치, 상담내용 250자·반복 검증이 기존 승인안이다.
- 코드 파일이 존재하는 사실만으로 공개 화면 반영 완료라고 쓰지 않는다. Q10의 진입 연결·화면·Description·배포 검증을 완료한 후 현행 문서로 이동한다.
