# 공통 UI·Description 작업 기준

기준일: 2026-11-06 (한국 시간). 업무 정책은 [현행 문서](../gfair_cs/docs/README.md)를 따른다.

## 검토 도구와 실제 화면

- common/의 상단 검토 도구·Description·핀·댓글은 실제 서비스 화면과 구분한다. 프로젝트는 gfair_cs, 공개 사이트는 기존 with-demo/html 주소를 유지한다.
- 상단 검정 영역은 With / 기획팀 SB, 화면 ID : 페이지명 선택, 기획정책, 사용구분, 기획비고·번호 표시·디스크립션 열기/닫기를 제공한다. 현재 구현에 없는 예전 새로고침·전체보기·확인시각 UI를 다시 추가하지 않는다.
- 기획정책은 새 창의 독립 페이지다. 서비스 화면 ID 선택과 Description 작성 대상에서 제외한다. 과거 화면검색 버튼·전체 목록은 현재 기획정책 진입으로 대체했다.
- 사용구분은 프로젝트별 localStorage에 보관하는 목업 검토값이다. 실제 로그인·서버 권한으로 간주하지 않는다. 첫 방문은 관리자이며 명시적인 목업 로그인·로그아웃의 기존 전환을 유지한다.
- 헤더는 이름님과 역할 배지를 표시하고 COM-06으로 이동한다. 역할을 사이드바 로고 아래·하단에 중복 표시하지 않는다. GTMS 원본 로고와 배경별 명암을 유지한다.
- 모바일은 메뉴 아이콘, QR·알림·로그아웃 아이콘을 표시한다. 알림·로그아웃 글자는 숨기고 접근성 이름은 유지한다. QR은 현재 역할·행사 문맥의 기존 진입 기능으로 연결한다.
- Description을 열어 왼쪽 표가 좁아진 데스크톱은 열을 숨기거나 내용을 잘라내지 않고 너비·줄바꿈을 조정한다. 대시보드는 가용 너비가 부족하면 한 열로 표시한다. 적용은 gfair_cs/css/description-preview.css다.

## 화면·폼·목록 배치

- 표준 주소는 index.html#화면ID다. 화면 선택·메뉴·직접 링크가 같은 ID를 사용하고 등록·상세·수정·팝업은 고유 ID를 등록한다. 과거 별도 HTML은 쿼리·해시를 보존하는 replace 이동으로만 호환한다.
- 제목은 왼쪽, 현재 위치는 오른쪽 같은 행이며 좁으면 현재 위치를 다음 행으로 내린다. 본문 제목 아래 화면 설명은 반복하지 않고 Description 개요에서 관리한다.
- 큰 묶음 제목은 표·콘텐츠 바깥에 작은 원형 불릿과 detail-section-title로 표시한다. 문자 O나 카드 안 헤더로 대체하지 않는다.
- 등록·작성·수정 표는 연한 회색 항목명·흰색 입력 셀·얇은 사각 구분선이다. 한 행 두 쌍, 단독/짝이 없는 항목은 전체 너비, 모바일은 한 쌍이다. 검색필터·로그인에는 이 작성 폼 레이아웃을 강제하지 않는다.
- 필수 항목은 항목명 옆 빨간색 #c62828 별표와 접근성 이름·required 검증으로 제공한다. 기존 필수 배지를 새로 사용하지 않는다.
- 기본 본문·상태·Description은 13px, 버튼은 13~14px다. 제목·강조 지표의 위계는 유지한다. 흑백 모노톤이며 필수·핀·기획비고 및 참가상태의 지정 색상만 예외다.
- 목록 데이터는 기본 가운데, 제목·내용·설명·사유·주소·비고·메모는 왼쪽, 헤더는 가운데다. 상세 진입 링크는 굵기 700·밑줄·키보드 접근을 유지한다. 이름으로 들어가는 목록에 행 전체 클릭을 추가하지 않는다.
- 건수 표시는 총 N건 · 현재페이지/전체페이지page이며 N은 굵게 표시한다. 검색·페이지당 수·페이지 이동과 실제 값을 맞춘다.
- 외부 연계에서 없는 값은 임의 값으로 채우지 않는다. 고유코드·ID·금액·국가·언어 값을 예시 규칙으로 임의 변환하지 않는다.

## 검색필터

- 분류·상태·기간 조건을 먼저, 키워드를 마지막 한 줄 전체 너비에 한 개만 둔다. 키워드 범위 선택·입력·검색·초기화를 같은 줄에 둔다.
- 항목명은 120px 회색 셀, 컨트롤은 흰색·36px 높이·적절한 너비다. 가용 너비와 조건 수에 따라 3열/2열, 모바일은 1열로 배치한다.
- 일반 조건 하나, 또는 2열의 홀수 마지막 항목은 전체 너비다. 기본 3열에서 두 조건만 남으면 각 1/3 너비를 유지한다.
- 고정 선택지 2~4개는 라디오, 연도·행사·동적/많은 선택지는 셀렉트·기존 다중 선택을 유지한다. 현재 화면의 예외·검증을 우선한다.
- 검색은 해당 필터 정의의 AND 결합·공백 제거·부분 일치·초기화를 유지한다. 검색항목·옵션은 각 Description에서 관리한다.

## 페이지 작업 버튼과 예외

- 목록·저장·등록·수정·삭제·제출 등 페이지 작업은 본문 우측 최하단 한 곳에 둔다. 검색·초기화·표 내부 행 조작은 기능 위치를 유지한다.
- 상단은 다운로드·업로드·동기화 같은 도구 기능이다. 삭제·제출은 회색 명도·대비로 구분하고 페이지 작업 버튼을 중복 표시하지 않는다.
- 버튼을 이동할 때 원래 폼·필수 검증·이벤트·키보드 동작을 유지한다. 버튼명은 목록·저장·등록·수정·삭제·제출처럼 짧게 쓰되 임시 저장 등 의미 구분은 보존한다.
- 예외: BAS-04·06·08의 목록·저장은 수정 정보 바로 아래·참가이력 위에 두고 상단 목록을 제공하지 않는다. 현재 행사 행별 이력 삭제는 해당 행에 둔다.
- 예외: BAS-03·05·07의 선택 미참여는 목록 상단 선택 작업 영역이다. BAS-15·COM-07 계정발송도 상단 도구다.
- 예외: PRE-01의 바이어 추가·숙소관리·다운로드는 상단 도구, 선택 인원·숙소 일괄변경·선택 바이어 제외는 표 위 선택 작업이다. 최종확정 버튼은 폐기했다.

## 기본 팝업 규칙

- 추가 팝업은 부모화면ID-pNN 형식이며 기존 유형 번호·고정 ID를 재정렬하거나 제목 해시로 바꾸지 않는다. 새 유형만 새 번호를 추가한다.
- 화면 ID·설명 버튼은 흰색 본문 밖 위의 검토 영역에 둔다. 제목과 X 닫기는 같은 행 중앙 정렬이며 접근 가능한 닫기 이름을 제공한다.
- 실행 버튼은 중앙 정렬·본문과 위 간격 15px다. 취소·폼 제출·필수/파일 검증을 유지한다. 페이지 작업 버튼의 우측 하단 규칙과 혼용하지 않는다.
- SET-13은 설문 미리보기 팝업이며 닫으면 이전 목록·편집 화면을 유지한다. COM-08 등록/상세, BAS-18 등록/상세는 현행 ID와 모드를 유지한다.
- 기본 처리는 gfair_cs/include/popup-description-example.js와 css에서 관리한다. 단순 배치 변경만으로 알럿/컨펌을 새로 만들지 않는다.

## 화면 변경 시 Description·알럿/컨펌 동시 반영

- 현재 사용자 지시를 우선하고 변경과 직접 관련된 내용만 수정한다. 무관한 문장·항목·기획비고의 전체 재작성·임의 생략을 하지 않는다.
- 항목·순서·옵션·유형·기본값·필수·권한·검증·버튼·이동·처리 결과가 바뀌면 화면·Description·메시지의 발생 조건·실제 문구·버튼·확인/취소·실패 처리를 같은 작업에서 맞춘다.
- 기존 설명 변경에는 기존 비고를 유지하고 [변경사항 있음 · YYYY-MM-DD] 변경 요약을 한국 시간으로 한 번 추가한다. 신규 초안 작성/등록 안내는 제외한다. 길이 제한 때문에 기존 비고를 잘라내지 않는다.
- ID·번호·댓글·저장 순서·핀 좌표를 유지한다. 항목 이동·추가·삭제로 필요한 연결과 표시 번호만 조정한다. 과거 MD나 기본 데이터로 서버 전체를 덮어쓰지 않는다.
- Codex가 바꾼 텍스트 범위만 markAgentChanges 메타데이터로 빨갛게 표시한다. 사용자 수정은 검정, 미수정 강조는 유지한다. 기획비고는 작성자·변경 여부와 관계없이 항상 빨간색이다.
- 하이픈+공백으로 시작한 줄만 점 목록이다. 일반 문장·들여쓰기·개행·빈 줄을 그대로 보존한다. 본문 HTML 태그·문장 자동 분할로 대체하지 않는다.
- 실제 화면·서버 저장 설명·알럿/컨펌·기획비고 조회를 대조한다. 로컬 초안만 고친 상태를 등록 완료로 보고하지 않는다. 문서/규칙만 바뀐 경우 개별 페이지 이력을 올리지 않는다.

## Description 작성·인증·핀

- Description은 기본 닫힘이며 탭의 열기 상태를 유지한다. 현재는 화면 개요와 영역 설명·알럿/컨펌 탭을 사용한다. 옛 고정 개요 표·명세·시트 로더·자동 시트 동기화를 다시 연결하지 않는다.
- 화면 개요는 화면 ID·화면명 아래에 둔다. 미구현 서버 연계를 완료로 단정하지 않는다. 기존 개요 설명과 알럿/컨펌을 섞지 않는다.
- 필수 작성 필드는 항목·유형·기본값·필수여부·기능상세다. 기본정책·예외·추가 상세 필드는 선택이다.
- 편집·삭제·기획비고 지우기·댓글 상태 처리는 GitHub 공동작업자 여부를 서버에서 검사한다. 이메일 수동 권한·ChatGPT 인증으로 대체하지 않는다. 일반 열람·비로그인 댓글은 현재 서버 정의를 따른다.
- 기획비고 행별 지우기는 planningNote만 비우고 본문·핀·댓글은 유지한다. 저장 시 revision 불일치는 409로 중단해 최신 내용을 조회한다.
- 영역 번호는 개요·알럿/컨펌을 제외한 설명만 01부터 연속 표시한다. 상단 번호 숨기기는 핀만 제어하며 본문·저장 위치를 바꾸지 않는다.
- 본문/현재 팝업 안의 고유 ID·입력 name·data 속성으로 대상을 유일하게 연결한다. 위치 경로는 마지막 수단이다. 문구 변경만으로 의미 기반 연결을 해제하지 않는다.
- 핀은 GitHub 공동작업자가 대상 영역 안에서 이동하며 저장 좌표·댓글을 보존한다. 저장 범위 ±4096px를 사용하고 저장 오프셋을 ±24px로 재축소하지 않는다. 크기·스크롤 변화에 재계산하고 화면 밖 대상의 핀을 가장자리에 남기지 않는다.
- COM-08 중복확인 설명은 등록 모드에만 표시하되 원본·댓글·다른 항목의 번호를 보존한다.
- 버전·한국 시간·표시 계정명과 이력은 gfair_cs/data/revision-history.js를 따른다. shyu 등 지정 표시명과 실제 Git 작성자는 구분한다. 신규 작업은 완료 전 소수 버전, 구현·설명·검증 완료 때 v1.0이며 완료 이력과 작업중 이력을 구분한다.
- 알럿/컨펌은 표시 유형·발생 상황 제목·조건·문구·확인/취소 결과를 기록한다. 유형만으로 제목을 만들지 않는다. 브라우저 기본 안내는 유효성 검사로 표시하고 언어·브라우저 차이를 명시한다.
- 공통 메시지는 MON-01, 다른 화면은 직접 관련 메시지만 표시한다. required·pattern·min/max 등 확인 가능한 브라우저 검증을 다루며 미구현 동작을 추가하지 않는다. 2026-10-29 초기화 전 기본 메시지를 자동 복원하지 않는다.

## 다운로드·원본 코드

- 현행 [엑셀 등록·다운로드](../gfair_cs/docs/엑셀_등록_다운로드.md)와 [회원·행사·계정](../gfair_cs/docs/회원_행사_계정.md)을 따른다.
- 국가·언어·산업군 기준은 사용자 제공 원본을 유지한다. 관심분야 제품 카테고리와 산업군·전시관을 혼용하지 않는다.
- 해외바이어는 ID/PW 없이 고유코드 QR을 사용한다. 행사 참가 상태·계정·QR의 사용 여부는 CP-03을 따른다.

## 공통 도구 구조

- 공통 서버 주소는 common/config.js 한 곳이다. 프로젝트별 설명은 프로젝트 ID·화면 ID를 함께 키로 사용한다.
- 새 프로젝트는 body data-project와 서버 프로젝트 등록·허용 복귀 URL을 함께 설정하고 공통 도구를 복제하지 않는다. GitHub App의 저장소 권한도 해당 프로젝트에 맞춰 확인한다.
- 계정·토큰·원시 서버 백업·개인 경로는 사이트 정책 데이터에 넣지 않는다. 원본 전달자료·과거 결과물의 정리 범위는 사용자의 별도 지시를 따른다.
